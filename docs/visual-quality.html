Sharper materials, readable combat

The scene already has a directional sun, hemispheric fill, a 2048 PCF shadow map, fog, selective glow, and a custom tiled terrain material. The next useful gains are coherent material response and contact shading. The initial dark ACES trial was rejected. Bright daylight now uses stronger illumination and character highlights, with no tone-mapping grade.

Compare the lighting trials

In the game, open F10 → Lighting. Bright daylight is the new initial default; the selection is remembered. These screenshots use the same camera, unit positions and animation poses.

Bright daylight strengthens the sun and sky fill and adds one shared edge light restricted to characters. Lower material roughness gives units broad highlights. The dark tone mapping and contrast grade are removed. FXAA uses a single direct pass. The soft-shadow variant adds PCSS at the existing map resolution, using Babylon's shadow filtering options. PCSS costs more than PCF, so it remains optional.

Both Bright daylight variants add one fullscreen pass. Six preset switches restored the original values exactly and kept mesh/material counts stable. Headless SwiftShader checks verify correctness; they do not establish frame rate on the player's GPU.

Recommended next experiments

These are recommendations from inspecting this game's materials and renderer. Effects below are not enabled by the lighting presets. Cost descriptions are relative estimates to profile.

PriorityVisible benefitImplementation and cost
1. Unit shadingClearer silhouettes, readable armor and faces, closer to a stylized MOBA.Test a soft lighting ramp and restrained rim light on the existing character materials. Keep thin instances, baked skinning, alpha cutouts, and shadows working. A shared fragment-material extension avoids a separate light per enemy.
2. Surface detailStone seams and metal catch the light instead of relying entirely on painted color.Author matching terrain normal/roughness maps, then test low-strength environment lighting for PBR units. The current Rapture exports use metallic 0 and roughness 1; their original toon shader is only approximated. Extra texture sampling and memory need measurement.
3. Contact shadingFeet, foliage, and ruins feel attached to the ground.Start with static AO/lightmap data for ruins and subtle instanced contact decals. Compare optional SSAO2 at reduced resolution only after checking its depth/normal passes against baked crowd animation. Avoid a separate shadow-casting light per unit.
4. Combat effectsDistinct hit sparks, muzzle bursts, dust and short trails make attacks easier to read.Use shared, bounded GPU particle emitters with an offscreen budget. Keep the existing selective glow. Large transparent smoke clouds can still be expensive because they shade overlapping pixels.
Later / optionalReflections or cinematic presentation for showcase views.SSR, global illumination, depth of field and motion blur need a separate visual/performance case. For regular MOBA play, prioritize sharp targets and unobscured telegraphs.

Primary references: MaterialPluginBase API · PBR materials · SSAO2 API · Babylon particles and Node Particle Editor. The installed Babylon source was also checked for the APIs used in the trials.

The enemies' leg animation

Pelican is the red enemy that fires three bullets in a spread. Its imported SD bundle contains idle and firing clips, but no walk. It previously moved using idle.

Pelican now borrows Crawler's compatible lower-body walk. Joint names, parent relationships and rest transforms are checked before the clip is baked. Pelican retains its own upper body and firing pose. This is reused Crawler animation, not a newly discovered native Pelican clip.

Crawler has clear native leg stepping. Lure has a much subtler native cycle that can look like gliding. The actual rendered skin was checked, not just the animation names: all three advance their walk frames during movement, and all original clips match fresh source imports within 0.001 world units. The cycles remain above ground. Names now appear above minion health bars using cached canvas labels.
